## REVIEW ADDENDUM (survey pass, 2026-07-06)

### CONTEXT

- Codebase: starlightr — R package (with a Rust/extendr core) that generates
  Astro Starlight documentation sites from R packages: Rd → MDX reference
  pages, vignettes/README → articles, example outputs captured and inlined.
  pkgdown analog. Version 0.1.0.9000, pre-release.
- Primary consumers: internal R developers at a2-ai documenting their own
  packages (e.g. hyperion, scicalc); runs interactively and in consumers' CI
  (a generated deploy workflow builds docs sites from tags).
- Known constraints or intentional decisions worth flagging up front:
  extendr-based native code; not currently on CRAN track. `extendr-api` on git
  branch `main` is NOT intentional — maintainer wants it pinned to the latest
  release (v0.9.0) [Q8]; report as a finding, not a known-intentional.
- Areas of specific concern: maintainer weights emitted-MDX correctness (Rust
  emitter) and R orchestration/config robustness equally [Q9] — do not skew
  effort toward one at the expense of the other.

### PRIORITY TARGETS

Roughly 80% of review effort here, each treated as a hypothesis to confirm or
refute.

1. **Silent content loss for unhandled Rd commands (emitter).** [Q1: confirmed
   defects for content-bearing commands — `\tabular`, `\preformatted`, `\pkg`,
   `\sQuote`, `\dots` and similar. The drop-with-stderr-note *mechanism* is
   intentional (maintainer's way of discovering tags without an exhaustive
   list) — don't flag the mechanism, flag the gaps.]
   The catch-all arm of `emit_command`
   (`src/rust/parser/src/emit/mdx.rs:139-149`) drops the full subtree of any
   unrecognized command with only an `eprintln!`. The lowering whitelist is
   `src/rust/parser/src/document/node.rs:128-142`. The insta corpus
   (`src/rust/parser/test_data/*.Rd`) contains only already-handled commands.
   Investigate: enumerate handled commands vs the Rd command set in "Writing R
   Extensions"; construct an Rd exercising `\tabular`, `\preformatted`,
   `\pkg`, `\sQuote`/`\dQuote`, `\cr`, `\tab`, `\env`, `\option`, `\file`,
   `\var`, `\dots`, `\Sexpr`; compare `emit_document` output against
   `tools::Rd2HTML`; classify each gap as content-dropping vs metadata-only.
2. **Config split-brain: three readers, drifted keys, inert defaults.**
   [Q2: maintainer confirms the R-side defaults were intended to apply —
   treat the inert-defaults path as a confirmed bug, not a question.]
   R merged config: `R/config.R:10-33` (+`default_config()` incl.
   `"docType"` at `R/config.R:66`); raw reader used by audit/helpers:
   `R/config_helpers.R:11-17`; Rust serde reader ([reference] only):
   `src/rust/parser/src/emit/options.rs:104-116`. Rust re-reads the file
   (`src/rust/parser/src/lib.rs:143`), so R-side defaults never reach it; key
   spellings `"docType"` / `"doc type"` / `"Doc Type"`
   (`src/rust/parser/src/document/sections.rs:27`) match only under exact
   lowercase equality (`node.rs:69-75`). Investigate: trace `skip_sections`
   and `section_order` end-to-end for a config with no `[reference]` table;
   check `merge_config` (`modifyList`) semantics on nested structures; map
   every config key to its consumer(s) and flag no-op keys.
3. **Duplicate resolution/escaping logic with confirmed drift.** [Q7]
   Globs: `R/build_site.R:193-201` vs `R/sidebar.R:134-149` vs
   `R/audit.R:347-372` — three semantics for the same config entry (sidebar
   handles trailing-`*` only and strips interior `*`). Escaping:
   `R/utils.R:131-138`, `R/sidebar.R:11-14`, `R/sidebar.R:42-44`, Rust
   `escape_yaml` (`mdx.rs:572`), plus **unescaped** YAML title interpolation
   in `R/build_articles.R:293-296` and `R/process.R:35`. Investigate: build a
   behavior table for the three glob impls on identical inputs; trace a
   quote-bearing title end-to-end; propose the single-boundary shape.
4. **Partial-failure behavior of the build pipeline.** [Q3]
   No `tryCatch` around the per-file render loop
   (`R/build_reference_files.R:82-90`); Rust batch path `?`-aborts on first
   bad file (`src/rust/parser/src/lib.rs:201-210`); example-capture errors
   swallowed via `message()` (`R/capture_example_output.R:122-127`); outputs
   written incrementally into the final `output_path` with no staging.
   Investigate: inject one malformed Rd into a scratch build; inventory
   warn/abort/swallow sites across `build_site`; assess deploy-workflow
   interaction (does the generated CI publish a half-built site?).
5. **Example capture in-session + `pkg` argument not threaded.**
   [Q4: in-session capture is deliberate for now — review capture
   *correctness*, not the isolation choice itself.]
   [Q5: `build_site(pkg = "../../pkg")` from e.g. a docs directory IS a
   supported use case — the cwd hardcoding is a confirmed bug. Maintainer
   adds a contract clarification: relative `output_dir` must resolve from the
   package root, not from cwd — audit every output-path resolution site
   against that rule.]
   In-session eval: `R/capture_example_output.R:65-79,114-127` (`library()`
   into caller session, env parented to `globalenv()`, hard requires
   ggplot2+gt) vs isolated callr subprocess for articles
   (`R/build_articles.R:79-102`). Separately `build_articles` hardcodes
   `normalizePath(".")` for `pkgload::load_all` (`R/build_articles.R:76`),
   dropping the documented `build_site(pkg=)` / `build_package_articles(pkg=)`
   contract; `render_reference` resolves relative `output_dir` against the
   process cwd (`src/rust/parser/src/lib.rs:58-64`); `patch_package_json`
   resolves it against `dirname(config_path)` (`R/config_helpers.R:743-749`).
   Investigate: confirm session mutation persists after capture; run the
   pipeline with `pkg != "."` from an unrelated cwd and record every place
   that resolves against the wrong root.

### KNOWN-INTENTIONAL / OUT OF SCOPE

Sources are maintainer interview answers `[Q#]` (2026-07-06) or in-repo
comments.

- The emitter's drop-unknown-command-with-stderr-note *mechanism* is
  intentional — it is the maintainer's discovery channel for Rd tags they
  don't have an exhaustive list of [Q1]. The individual content-dropping gaps
  are still in scope (priority target 1); the pattern itself is not a finding.
- In-session example execution (vs subprocess) is accepted for now [Q4] — do
  not flag the isolation choice; capture *correctness* remains in scope.
- `add_*` config helpers losing user comments/formatting in
  `_starlightr.toml` is accepted — tomledit cannot preserve formatting [Q7].
- Generated code is out of scope for style/structure findings:
  `R/extendr-wrappers.R` ("Generated by extendr: Do not edit by hand"),
  `man/*.Rd` (roxygen2), `README.md` (from README.Rmd).
- `\dontrun{}`/`\donttest{}` examples are deliberately not executed
  (README: "`\dontrun{}` and `\dontshow{}` in Rd are respected";
  `R/capture_example_output.R:17-24`).
- `index.mdx`, `package.json`, `.gitignore`, deploy workflow in the output
  site are user-owned and deliberately not overwritten without
  `overwrite = TRUE` (comments at `R/pages.R:66-67`, `R/generate.R:86-89`).
- `custom.css` never overwritten / `starlightr.css` always overwritten —
  stated ownership split (`R/generate.R:174-213` roxygen comments).

  `tools/config.R` + `Makevars.in` are deliberate CRAN/webR accommodations
  (comments in both files).

### REPO MAP

(Section 1 of the survey, verbatim; items marked `(?)` should be re-verified
rather than trusted.)

**Purpose.** `starlightr` is a pkgdown-style documentation-site generator: it
turns an R package's Rd files, vignettes, README, and NEWS into an Astro
Starlight site (Rd → MDX reference pages, Rmd → markdown articles, captured
example outputs embedded inline). Codebase type: **hybrid** — an R package
(orchestration/config layer, ~3.5k lines under `R/`), a Rust workspace exposed
via extendr (`src/rust/`, the Rd lexer/parser/MDX emitter), and a set of
JS/Astro/YAML site templates shipped in `inst/templates/`.

**Entry points** (all R exports, `NAMESPACE`):
- `build_site()` — `R/build_site.R:33`, the main orchestrator.
- `use_starlightr()` — `R/use_starlightr.R:21`, scaffolding.
- `audit_config()` — `R/audit.R:25`, config-vs-NAMESPACE audit (also run
  automatically at the top of `build_site`).
- `build_reference_files()` / `build_package_reference_docs()` —
  `R/build_reference_files.R:34,129`.
- `build_articles()` / `build_package_articles()` — `R/build_articles.R:28,161`.
- `render_reference()` — extendr wrapper (`R/extendr-wrappers.R:28`) →
  Rust `render_reference` (`src/rust/parser/src/lib.rs:126`).
- Config helpers: `add_card`, `add_action`, `add_reference`, `add_article`,
  `add_version`, `add_package`, `get_/set_reference_sections`,
  `get_/set_article_sections` — `R/config_helpers.R`.
- Note: Rust also exports `render_references` (dir-walking batch variant,
  `src/rust/parser/src/lib.rs:162`) with a generated wrapper at
  `R/extendr-wrappers.R:30`, but it is **not** in `NAMESPACE` and has no R
  callers [confirmed — intended export that never landed, Q10; see OPEN HUNT].

There are no services, background workers, or scheduled tasks. The generated
site ships a GitHub Actions template (`inst/templates/deploy-docs.yml`) that
runs in *consumers'* repos, not here.

**Module inventory** (R layer):
- `R/build_site.R` (260) — pipeline orchestrator; `resolve_config_rd_files` /
  `resolve_config_rmd_files` (config→file resolution incl. one glob impl).
- `R/config.R` (93) — `read_config` (TOML + `modifyList` merge with
  `default_config()`); used **only** by `build_site` and
  `build_package_reference_docs` (?).
- `R/config_helpers.R` (836) — programmatic TOML editing via `tomledit`
  (read raw / modify list / rewrite whole file); all `add_*` helpers.
- `R/audit.R` (372) — NAMESPACE parsing, config-reference matching (second
  glob impl), link auditing.
- `R/sidebar.R` (507) — builds the Starlight sidebar **as a JS string** via
  sprintf; third glob impl (`expand_glob_patterns`), pkgdown selector
  expansion, Rd-db lookups for `@rdname`.
- `R/build_reference_files.R` (221) — reference pipeline: example capture →
  external-link map → per-file Rust render.
- `R/capture_example_output.R` (180) — parses and **evals `@examples` in the
  current R session**, captures ggplot (PNG), gt (HTML), and printed text.
- `R/build_articles.R` (402) — renders Rmd in a `callr` subprocess via
  `pkgload::load_all`, copies figures to `public/figures/<slug>/`, rewrites
  image paths, prepends frontmatter.
- `R/external_links.R` (99) — builds `pkg::topic → URL` JSON map from installed
  packages' `aliases.rds` + DESCRIPTION URL.
- `R/generate.R` (215), `R/versions.R` (155), `R/assets.R` (67),
  `R/pages.R` (179), `R/process.R` (49) — template rendering (whisker), version
  support files, asset/logo copying, index.mdx and news.mdx generation.
- `R/links.R` (254) — link classification/validation for the audit.
- `R/utils.R` (252) — `%||%`, `slugify`, `escape_quoted_string`, template I/O.
- `R/rd_postprocess.R` (49) — `evaluate_sexpr`; no callers found (?) (dead).
- `R/extendr-wrappers.R` — generated.

**Module inventory** (Rust, `src/rust/`):
- `lib.rs` + `document.rs` — extendr module glue + wrapper regeneration binary.
- `parser/src/parsing/` — `lexer.rs` (228, hand-rolled Rd lexer),
  `parser.rs` (221, recursive-descent to `Node` tree), `span.rs`.
- `parser/src/document/` — `node.rs` (Node enum + `lower()` dispatch),
  `sections.rs`, `list.rs`, `link.rs`, `code.rs` — lowering of raw commands
  into typed nodes (Section, List, Link, Code, ArgumentTable).
- `parser/src/emit/` — `mdx.rs` (788, the emitter: frontmatter, sections,
  argument tables, math/code modes, external links, inline example outputs),
  `options.rs` (its own serde TOML `Config` reader — reads **only**
  `[reference]`).

**Intended layering** (inferred from call graph): exported R functions →
R orchestration (config/capture/articles) → Rust `render_reference` for
Rd→MDX → whisker templates for site chrome. Data crosses the R↔Rust boundary
via file paths + two temp JSON files (external links, example outputs) rather
than in-memory structures.

**Most load-bearing files:**
1. `src/rust/parser/src/emit/mdx.rs` — every reference page's content passes
   through it.
2. `R/build_site.R` — the only composition point; every build flows through.
3. `R/config_helpers.R` + `R/config.R` — config is read by three independent
   readers; these define the de facto schema.

**Cross-cutting concerns:**
- *Errors*: R mixes `cli::cli_abort`, base `stop()`, `cli_warn`,
  warn-and-continue, and `message()`-and-swallow (example capture,
  `R/capture_example_output.R:122-127`). Rust converts everything to
  `extendr_api::Error::Other` strings via `ResultExt`
  (`parser/src/lib.rs:16-24`); parse errors get line/col context.
- *Config*: three readers — `read_config` (merged with defaults,
  `R/config.R:10`), `read_config_toml` (raw, `R/config_helpers.R:11`, used by
  audit + all helpers), and Rust `Config::read_config`
  (`parser/src/emit/options.rs:109`, `[reference]` only).
- *Logging*: `cli` alerts throughout R; Rust warns via `eprintln!`
  (`mdx.rs:141-147`).
- *Validation*: `audit_config` validates config↔NAMESPACE/links up front;
  input Rd/Rmd content itself is trusted.
- *Concurrency*: none (single-threaded R; `callr::r_safe` subprocess per Rmd;
  Rust is synchronous). Category C is essentially N/A (?).

**Build/test/CI shape:** R package with `configure`/`tools/config.R` writing
`src/Makevars` (cargo static lib, vendored-offline support, webR/WASM path).
CI is one workflow (`.github/workflows/R-CMD-check.yaml`): R CMD check on
Windows/macOS/Linux × R 4.5/4.6, deps via `rv`. `cargo test` is not run in
CI [confirmed, Q6] — the Rust snapshot suite (insta, 10 Rd corpus files × lex/parse/emit)
runs only via local `lefthook.yaml` pre-commit. R-side testthat coverage is
3 small unit tests (`tests/testthat/`). Rust dep `extendr-api` is pinned to
git `branch = "main"` (Cargo.lock committed).
