# starlightr — Deep Architecture & Code Review (pass 2)

Date: 2026-07-06. Read-only review. Scope and priority targets per the survey
addendum; every claim below re-verified against the current source.

---

## 1. Architecture summary

`starlightr` is a pkgdown-style static-site generator: it turns an R package's
`man/*.Rd`, vignettes/README, and NEWS into an Astro Starlight site. It is a
**hybrid**: an R orchestration layer (`R/`, ~3.5k LOC), a Rust/extendr core
(`src/rust/parser/`: hand-rolled Rd lexer -> recursive-descent parser -> `Node`
lowering -> MDX emitter), and JS/Astro/YAML templates shipped in
`inst/templates/` that execute in *consumers'* sites and CI.

**Entry points spot-checked (all verified):** `build_site()`
(`R/build_site.R:33`) is the sole composition point; `use_starlightr()`,
`audit_config()`, `build_reference_files()`/`build_package_reference_docs()`,
`build_articles()`/`build_package_articles()`, the `add_*`/`get_*`/`set_*`
config helpers, and the extendr `render_reference()`/`render_references()`
wrappers. The map's "most load-bearing files" (`emit/mdx.rs`, `build_site.R`,
`config_helpers.R`+`config.R`) and the "three config readers" claim are all
confirmed. Concurrency (Category C) is genuinely N/A (single-threaded R; one
`callr` subprocess per Rmd; synchronous Rust) — confirmed cheaply, not dwelt on.

**Flows traced.** (a) *Happy path build*: `build_site` -> `audit_config` ->
`read_config` (merge with `default_config`) -> scaffold dirs/templates ->
`resolve_config_rd_files` -> `build_reference_files` (capture examples in-session
-> external-link JSON -> per-Rd `render_reference` in Rust) -> `build_articles`
(callr `load_all` + `rmarkdown::render`, figures copied) -> `generate_astro_config`
(sidebar as a JS string). (b) *Config->emitter*: R reads config for file
selection, but Rust **re-reads the same TOML file itself** and only honours the
`[reference]` table — the R-side merged defaults never cross the boundary. (c)
*Error path*: a malformed Rd aborts `render_reference`, which aborts the
un-guarded per-file loop, which aborts all of `build_site`, mid-write into the
live output directory.

**Structural read.** The Rd->MDX core is clean and well-factored (typed `Node`
lowering, focused emitter methods, an insta snapshot suite). The systemic risk
is concentrated at **boundaries**: the R<->Rust config boundary (two readers that
disagree), the R<->shell/site boundary (string interpolation without a single
escaping discipline), and the "same concept implemented three times" pattern
(globs) — all classic drift generators. The default scaffold exercises the
worst config path, so several of these fire for ordinary first-time users, not
just edge cases.

**Priority-target verdicts (survey hypotheses):** PT1 **confirmed** (content-
bearing gaps real; drop-mechanism itself out of scope per Q1). PT2 **confirmed
and elevated** — the inert-defaults path is the *default scaffold*, not an edge
case. PT3 **confirmed** (three glob semantics diverge; YAML title unescaped).
PT4 **confirmed** (no guard, no staging). PT5 **confirmed** (cwd hard-coded;
capture mutates the session; multi-output collapse).

## 2. Primary findings (ranked)

### F1 — `[reference]` config defaults never reach the Rust emitter; section skip/order is inert on the default scaffold
- **Status: Fixed on branch `v0.2.0` (2026-07-06).** `build_reference_files()` now reads the merged config via `read_config()` and writes just the resolved `reference` table to a temp TOML consumed by the Rust emitter (`R/config.R:write_reference_config_toml`), instead of pointing Rust at the raw user file. Default `skip_sections` spelling changed `"docType"` -> `"Doc Type"` to match the emitted section key. Regression tests in `tests/testthat/test-reference-config.R`. Rust side untouched — `Config`/`EmitOptions` still only reads `[reference]`, it's just fed correct data now. `render_references` (the orphaned batch export, F1 note in "beyond top 9") was left as-is — out of scope for this fix.
- **Severity: High · Category: A/D (boundary + duplicated readers) · Confidence: High**
- **Evidence:** `R/config.R:40-79` (`default_config()` sets `reference$skip_sections`, `section_order`), `R/config.R:10-33` (`read_config` merges via `modifyList`); but `R/build_reference_files.R:82-90` passes the *path* `config_path` to Rust, and `src/rust/parser/src/lib.rs:143` (`EmitOptions::from_file`) -> `src/rust/parser/src/emit/options.rs:29-48,108-115` re-parses the file, reading only `[reference]`. The scaffolded config (`inst/templates/starlightr.toml`) contains **only `[site]` and `[output]`** — no `[reference]` table. So `config.reference = None` -> `EmitOptions::default()` -> `skip_sections = []`, `section_order = []`.
- **The issue:** For every package initialised with `use_starlightr()` and built with `build_site()`, the Rust emitter skips *nothing* and orders *nothing*. `\name`, `\alias`, `\title`, `\keyword`, `\concept`, `\docType` all render as visible `## ` H2 sections in every reference page body — duplicating the frontmatter title/sidebar label and dumping keyword/alias/doctype noise into the page. The R merge that was written to prevent exactly this is dead weight because it is on the wrong side of the boundary.
- **Secondary drift (same finding):** even when a user *does* add a `[reference]` table copying the defaults, `skip_sections = ["docType"]` never matches. `node.rs:69-75` compares `to_lowercase()` of the skip entry against the section key, and `sections.rs:27` lowers `docType` to the key `"Doc Type"` -> `"doctype" != "doc type"`. The emitter's own test uses the *correct* spelling `"doc Type"` (`mdx.rs:709`), so the shipped default has silently drifted from the tested value.
- **Blast radius:** every default build produces cluttered reference pages; nobody notices until they compare to the intended (tested) output. Q2 confirms the R defaults were meant to apply.
- **Remediation:** make R the single source of truth — have `build_reference_files` write the *merged* `reference` options to a temp TOML (or pass them as explicit args to the extendr call) and point Rust at that; delete the second reader or reduce it to a pure deserializer fed by R. Fix the `docType`/`"Doc Type"` spelling and add a round-trip test asserting default skips actually apply. ~1 day.

### F2 — Silent content loss for unhandled content-bearing Rd commands
- **Status: Fixed (2026-07-06).** `emit_command` (`src/rust/parser/src/emit/mdx.rs`) now has arms for `tabular` (renders a GFM table by splitting the body on bare `\tab`/`\cr` commands — see `split_by_bare_command`/`emit_table_row`/`emit_tabular`), `preformatted` (fenced code block), the backtick-style inline wrappers `pkg`/`env`/`option`/`file`/`command`/`samp`/`kbd` (reuse `emit_code`), `var`/`dfn` (reuse `emit_emph`), `sQuote`/`dQuote` (new `emit_wrapped` helper), `acronym`/`cite` (plain passthrough), `out` (new `emit_out` — passes through unescaped, since it was so far exclusively observed nested in `\ifelse{html}{...}` and is meant to insert raw markup/entities), and `enc` (emits the first, UTF-8 argument). `\Sexpr` is deliberately left unhandled — it requires evaluating R code at doc-build time, which is out of scope for a static Rust re-implementation of the emitter; it still falls through to the existing catch-all (stderr warning + drop), same as before. `\cr`/`\dots` outside of a `\tabular` body remain cosmetic no-ops per the original finding. Corpus grown from 10 to 22 `test_data/*.Rd` fixtures, all real excerpts pulled from public sources (R base/recommended/datasets via the `wch/r-source` GitHub mirror, plus `survival`, `partitions`, and `data.table`), each with a `% Pulled from <url>` citation per the maintainer requirement below. Regenerated insta snapshots for all four glob-based tests (`can_lex_rd_files`, `can_parse_rd_files`, `can_emit_rd_files`, `can_skip_sections`, `can_order_sections`); no pre-existing snapshot changed, confirming no regressions. **Follow-up gap (bare `\item` pairs in `\value`) fixed 2026-07-06.** New `group_bare_item_pairs()` (`src/rust/parser/src/document/sections.rs`), called from `lower_titled_section()`, scans a titled section's children for maximal runs of bare `Command{name: "item", ...}` nodes and collapses each run into a `Node::List{kind: Describe, ...}` — the same structure `\describe` already produces, so it renders through the existing `emit_describe_list` with no emitter changes needed. Whitespace/newline nodes between consecutive `\item`s (ordinary Rd source layout) are treated as insignificant and don't break the run — an earlier version of this fix didn't account for that and fractured one 8-item list into 8 separate one-item lists with stray blank lines between them; caught by inspecting the actual rendered snapshot, not just that the code compiled. New fixture `test_data/base-platform.Rd` (real excerpt: base R's `.Platform`, whose `\value` section is exactly this pattern — the file dropped from F2's corpus for this reason is now used for what it was originally picked to demonstrate). New snapshots for all five glob-based tests; no pre-existing snapshot changed. **New gap found while validating against this fixture, logged separately as F11 below rather than fixed here (kept this pass scoped to the item-pairs fix):** `\bold` isn't mapped to `emit_strong` the way `\strong` is, so `\bold{O}perating \bold{S}ystem` silently drops the wrapped letters, not just the emphasis — visible throughout `base-platform.Rd`'s rendered output.
- **Severity: High · Category: B/E · Confidence: High**
- **Evidence:** catch-all arm `src/rust/parser/src/emit/mdx.rs:139-148` drops the entire subtree of any command not matched at `mdx.rs:126-137` and not in the lowering whitelist (`document/node.rs:128-142`). Handled set is fully enumerable: `code/verb, emph, strong, eqn, deqn, email, method/S3method/S4method, if, ifelse, figure`, list/link/section/code families, and math-mode passthrough. The insta corpus (`src/rust/parser/test_data/*.Rd`) uses **only handled commands** (verified: `grep` for `\tabular|\preformatted|\pkg|\sQuote|\Sexpr|...` over the corpus returns nothing).
- **The issue:** content-bearing commands hit the catch-all and their *text is discarded*, not just their markup. Confirmed content-dropping: `\tabular` (whole table), `\preformatted` (whole block), and the inline text-wrappers `\pkg`, `\sQuote`/`\dQuote`, `\var`, `\env`, `\option`, `\file`, `\command`, `\samp`, `\acronym`, `\cite`, `\kbd`, `\dfn` (wrapped words vanish), plus `\Sexpr`, `\out`, `\enc`. `\cr`/`\dots` are cosmetic. Per Q1 the drop+stderr *mechanism* is intentional; the **gaps** are the finding.
- **Blast radius:** any real package using tables or `\pkg{...}`/`\sQuote{...}` in prose (common) loses that content from the published docs, silently — the `eprintln!` goes to a build log nobody reads, and no CI runs the emitter (see F9).
- **Remediation:** add minimal emit arms for the inline wrappers (map to backticks / quotes / plain text) and `\tabular` (-> MDX table), and — critically — grow the snapshot corpus to include them so the gap is visible. ~1-2 days for the common set.
- **Maintainer requirement (added 2026-07-06, before implementation):** every new `test_data/*.Rd` fixture added for these tags must be an actual excerpt copied from a real package's `man/*.Rd` file (e.g. CRAN packages, or internal packages like hyperion/scicalc) — not a synthetic snippet authored for the test. Cite the source package/file for each addition. This mirrors the existing corpus convention (`dplyr-storms.Rd`, `hyperion-package.Rd`, `scicalc-*.Rd` are all real files) and must hold for the `\tabular`/`\preformatted`/`\pkg`/`\sQuote`/etc. additions too.

### F3 — `build_articles` hard-codes cwd; output-path resolution has no single rule
- **Status: Fixed (2026-07-06).** `build_articles()` now takes a `pkg = "."` argument, resolves it once to `pkg_path`, and uses that (not `normalizePath(".")`) for the `pkgload::load_all()` call in the callr subprocess. A single new helper, `resolve_against(path, base)` (`R/utils.R`), is the one rule for turning a possibly-relative output dir into an absolute path against the package root; `build_articles()` and `build_reference_files()` both call it on `output_dir` before doing anything else, so a relative `output_dir` always resolves against `pkg`/`pkg_path`, never the caller's cwd. `build_site()` now passes `pkg = pkg_path` into `build_articles()` (it already did for `build_reference_files()`), and `build_package_articles()` passes its own resolved `pkg_path` down the same way. Because `build_reference_files()` now always hands Rust's `render_reference()` an absolute `output_dir`, `lib.rs`'s `std::env::current_dir()` fallback in `resolve_output_file_path` is no longer reachable from any R entry point (left as-is — untouched, and out of scope while another pass has an active `cargo test` running against this crate). `patch_package_json`'s `dirname(config_path)` root was left alone too: it has no `pkg` argument to thread, and since `config_path` is always `file.path(pkg_path, config_file)` at every call site, `dirname(config_path) == pkg_path` already holds — not actually divergent in practice, just independently computed. Verified with a throwaway two-directory fixture (`pkg` at one path, cwd at an unrelated sibling): pre-fix code failed with pkgload's "Could not find a root 'DESCRIPTION' file" error (the cwd bug, reproduced), post-fix code renders correctly and writes into `<pkg>/<relative output_dir>` regardless of cwd. Regenerated `man/*.Rd` for the three touched exports via `roxygen2::roxygenise()`, keeping `DESCRIPTION`'s `RoxygenNote`/`Config/roxygen2/version` pinned as before (local roxygen2 is a newer major version than the repo targets).
- **Severity: High · Category: A/D · Confidence: High**
- **Evidence:** `R/build_articles.R:76` `pkg_path <- normalizePath(".", mustWork = TRUE)` then `load_all(pkg_path)` in the callr subprocess (`:79-102`). `build_articles()` takes no `pkg` argument, and `build_site` (`build_site.R:126-132`) calls it with rmd paths resolved from `pkg_path` but no way to pass the root. Meanwhile relative `output_dir` is resolved against **three different roots**: Rust `resolve_output_file_path` uses `std::env::current_dir()` (`lib.rs:58-64`); `patch_package_json` uses `dirname(config_path)` (`config_helpers.R:743-749`); `build_site` uses `pkg_path` (`build_site.R:62-66`).
- **The issue:** `build_site(pkg = "../../pkg")` from a docs directory (a supported use case per Q5) makes the article subprocess `load_all(".")` — loading the *wrong* package (or failing), so vignettes render against the wrong namespace. Q5 states the contract: relative `output_dir` must resolve from the package root; the Rust path and the article path both violate it.
- **Blast radius:** anyone building docs from outside the package root gets wrong/empty article output or a hard error, with no diagnostic pointing at the cwd assumption.
- **Remediation:** thread `pkg` (the resolved `pkg_path`) into `build_articles`/`process_article_inline` and into the `render_reference` call as the base for relative outputs; resolve all relative output dirs against `pkg_path` in one helper. ~0.5-1 day.

### F4 — Three divergent glob implementations for `sidebar.reference`
- **Status: Fixed (2026-07-06).** Extracted `expand_reference_patterns(patterns, candidates)` (`R/utils.R`) as the single glob semantics — `*` anywhere in the token, full `.*` expansion, anchored on both ends, case-insensitive — and pointed all three call sites at it: `R/build_site.R:resolve_config_rd_files` (already closest to this semantics, simplified to a one-line call), `R/sidebar.R:generate_sidebar_config` (replaced the trailing-only, case-sensitive `expand_glob_patterns`, which is deleted; result is still `sort()`-ed at the call site to preserve the sidebar's alphabetical display order), and `R/audit.R:match_single_reference` (replaced its trailing-only glob branch; the `-package` and pkgdown-selector special cases, which are orthogonal to the glob divergence, were left as-is). New unit tests in `tests/testthat/test-utils.R` cover leading/interior/trailing globs, case-insensitivity, cross-pattern dedup, and no-match. Full suite: 22/22 passing.
- **Severity: High · Category: A · Confidence: High**
- **Evidence:** (i) file selection `R/build_site.R:193-201` — any `*`, `*`->`.*`, anchored `^...$`, **case-insensitive**; (ii) sidebar `R/sidebar.R:134-149` (`expand_glob_patterns`) — **trailing `*` only**, strips *all* `*` (not `->.*`), prefix-anchored `^...` with **no end anchor**, **case-sensitive**; (iii) audit `R/audit.R:360-363` (`match_single_reference`) — **trailing `*` only**, `*`->`.*`, anchored `^...$`, case-insensitive.
- **The issue:** the same config token is interpreted three ways. A leading/interior glob (`*_helpers`, `a*b`) **selects and renders** an Rd file (impl i) but is treated as a literal by the sidebar (impl ii -> absent from the sidebar) and by audit (impl iii -> "config reference doesn't match export" false warning). An uppercase glob (`Build*`) renders (i, case-insensitive) but never appears in the sidebar (ii, case-sensitive). Net: pages get generated that are unreachable from navigation, while the audit cries wolf about them.
- **Blast radius:** silent orphaned pages + noisy false audit warnings for any non-trailing or mixed-case glob; grows with every package that uses selectors.
- **Remediation:** extract one `expand_reference_patterns(patterns, candidates)` used by all three sites, with one documented semantics (case-insensitive, full `*`->`.*`, anchored). ~0.5 day.

### F5 — No single escaping boundary; user text is interpolated raw into YAML/MDX/TS/JS across the R layer
- **Status: Fixed on branch `v0.2.0` (2026-07-06).** Reproduced first: an article/vignette title containing `"` (e.g. `A "Quoted" Title`) produced YAML frontmatter that failed `yaml::yaml.load()` — confirmed the build-breaking claim before touching any code. Fix keeps `escape_quoted_string()` (`R/utils.R`) as the single escaper for every YAML-double-quoted-string / JS-or-TS-string-literal interpolation point, and adds two new purpose-built escapers next to it for the two other target syntaxes the finding named: `escape_mdx_attr()` (JSX/MDX double-quoted attribute values — `"`/`&` -> entities, since JSX attribute strings don't support backslash escapes) and `escape_mdx_text()` (MDX body text — escapes a bare `<` the same way the Rust emitter's own `escape_mdx_text` in `src/rust/parser/src/emit/mdx.rs` already does, for consistency with the one part of the codebase that already had this right). Routed every raw-interpolation site the finding cited through one of these: article title (`R/build_articles.R:process_article_inline`), NEWS title (`R/process.R:process_news`), site title — previously **entirely unescaped**, not just inconsistently escaped (`R/pages.R:create_index_page`), hero action text/link and the default-actions GitHub link (`R/pages.R`, also newly quoted — it was interpolated unquoted into a YAML plain scalar before), Card `title`/`icon` (now MDX-attribute-escaped) and Card `description` (now MDX-text-escaped), the two ad hoc sidebar escapers `make_sidebar_item`/`make_sidebar_group` (`R/sidebar.R`, both now delegate to `escape_quoted_string` instead of their own partial quote-only/quote+backslash gsubs), and `github_url` in `astro.config.mjs` (`R/generate.R`; the template's `href` was switched from single- to double-quoted JS string so the same double-quote escaper applies consistently with `title` in the same file). Separately fixed `versions.ts`: it was rendered through whisker's default `{{ }}` (HTML-escaping — wrong target syntax, produces literal `&quot;` inside a TS string and doesn't touch backslash/newline), swapped to `{{{ }}}` (raw) with `tag`/`label`/`currentVersion` pre-escaped via `escape_quoted_string()` in `R/versions.R`. **Left as-is (out of scope):** Card `link` — it sits inside a Markdown link destination `(%s)`, not a quoted string or MDX text node, so a `)` in it is a distinct (Markdown-syntax) corruption vector from the quote/attribute escaping this fix addresses; would need URL-destination escaping, a separate finding. New regression tests in `tests/testthat/test-escaping.R` (14 tests) cover the two new escapers directly and exercise every fixed call site end-to-end with adversarial (quote/backslash/ampersand/`<`) input, asserting the YAML output round-trips through `yaml::yaml.load()` and the MDX/JS output contains the expected entity/backslash escapes rather than a raw break. Full suite: 23/23 `test_that()` blocks passing, 0 failures (`testthat::test_dir`). Rust side untouched — its own `escape_yaml`/`escape_mdx_text`/`escape_html` (`mdx.rs`) were already correct; this finding was scoped to the R layer.
- **Severity: Medium · Category: D · Confidence: High**
- **Evidence:** unescaped: article & NEWS frontmatter titles `R/build_articles.R:293-298` and `R/process.R:35` (`paste0('title: "', title, '"')`); index.mdx Card `title`/`description`/`link`/`icon` `R/pages.R:135-146` (`sprintf` raw); `inst/templates/versions.ts:11-12` use double-mustache `{{ }}` (whisker HTML-escapes -> `&quot;` in a TS string, and backslash/newline breaks the module), fed unescaped by `R/versions.R`; `astro.config.mjs` `{{{github_url}}}` unescaped (`R/generate.R:56-67` escapes only `title`). Partial/duplicated escapers that disagree: `escape_quoted_string` (`utils.R:131-138`, full), `make_sidebar_item` (`sidebar.R:11-13`, quotes only — **no** backslash), `make_sidebar_group` (`sidebar.R:42-43`, quote+backslash), hero actions (`pages.R:99-113`, quotes only), and Rust `escape_yaml` (`mdx.rs:572`, backslash+quote). The Rust *Rd*-title path escapes; the R *article*-title path does not.
- **The issue:** a vignette/NEWS/config value containing `"`, `\`, or a newline produces malformed frontmatter/MDX/TS and breaks the Astro build of the generated site — and there is no one place to fix it because each call site rolls its own (or no) escaping.
- **Blast radius:** hard-to-diagnose downstream build failures in consumers' sites; the failure surfaces in `bun run build`, far from the R code that emitted the bad string.
- **Remediation:** one escaper per target syntax (YAML string, JS/TS string literal, MDX attribute) applied at every interpolation point; route all sidebar/card/version emitters through them. Add tests with quote/backslash-bearing titles. ~1 day.

### F6 — No partial-failure handling and no output staging; one bad file corrupts a published site
- **Status: Fixed (2026-07-06), two parts.** (1) *Per-file failure handling:* the per-Rd-file loop in `build_reference_files()` (`R/build_reference_files.R`) now `tryCatch`es each `render_reference()` call, collects failures, renders the rest, and reports one bulleted `cli_warn` summary; `capture_rd_examples()`'s (`R/capture_example_output.R`) three swallow-via-`message()` sites were switched to the same collect-and-report pattern, so both halves of the pipeline share one warn-and-skip policy instead of disagreeing. New tests: `tests/testthat/test-build-reference-partial-failure.R`, `tests/testthat/test-capture-example-partial-failure.R`. (2) *Output staging/atomic swap:* `build_site()` (`R/build_site.R`) now builds the `reference/` and `articles/` content directories — the two subtrees driven by per-file loops over user-supplied `.Rd`/`.Rmd` files — into a temporary sibling directory via a new `build_into_staged_dir()` helper (`R/utils.R`), and atomically `file.rename()`s it into place only once that directory's build returns without error. An uncaught failure partway through (anything outside the per-file `tryCatch`'s scope — an I/O error, an interrupt, a bug) now leaves that directory exactly as the last successful build left it, never a mix of stale and partial files. **Deliberately scoped to just those two directories, not the whole `output_path`:** a wholesale site-root swap would also discard files/dirs starlightr never manages (`node_modules/`, a nested `.git/`, editor state) that happen to live under `output_dir`, and would need to replicate the existing-file guards on `custom.css`/`package.json`/`.gitignore`/`index.mdx`/the deploy workflow (each keyed on `output_path`) before writing into a fresh staging copy — treated as a separate, larger change than this finding's remediation called for. New tests: `tests/testthat/test-utils.R` (`build_into_staged_dir`: publishes on success, wholesale-replaces stale pre-existing content, leaves `final_dir` byte-for-byte untouched when the build function errors, creates `final_dir` when it doesn't exist yet). Rust-side `render_references` batch abort (`lib.rs:201-210`) and the `deploy-docs.yml` `bash -eo pipefail` behavior were left as-is — out of scope for this fix (the deploy job already fails closed rather than publishing a half-built site, just publishes nothing for that run).
- **Severity: Medium · Category: B · Confidence: High**
- **Evidence:** per-file render loop has no `tryCatch` (`R/build_reference_files.R:82-90`); `render_reference` `?`-propagates the first parse/emit error (`lib.rs:158`), and the batch `render_references` aborts on first bad file (`lib.rs:201-210`); example-capture errors are swallowed via `message()` instead (`R/capture_example_output.R:122-127`) — the opposite extreme. Outputs are written directly into the final `output_path` (`build_site.R:62-66,109`), never a staging dir. Deploy loop `inst/templates/deploy-docs.yml:47-75` runs under `bash -eo pipefail`, so one un-buildable historical tag aborts the whole job (publish is a separate gated step, so it does *not* push a half-built site — but it publishes *nothing*).
- **The issue:** the de facto error strategy is incoherent — reference rendering is fail-fast-and-abort, example capture is swallow-and-continue. A single malformed Rd aborts all of `build_site` after it has already overwritten CSS/templates and written some `.mdx` into the live directory, leaving a partially regenerated site. In CI a re-run against a tag with one bad Rd never publishes any version.
- **Blast radius:** interactive users get a corrupt output dir; CI users get no site from one bad file. Grows with corpus size.
- **Remediation:** wrap the per-file loop in `tryCatch` that collects failures and reports a summary (render the rest); build into a temp dir and atomically swap on success; decide one policy (warn-and-skip) and apply it in both languages. ~1 day.

### F7 — Example capture mutates the build session and silently drops all-but-last outputs
- **Status: Fixed (2026-07-06).** All three sub-issues fixed in `capture_rd_examples()` (`R/capture_example_output.R`): (1) *session mutation* — now records whether the target package was already attached before its own `library()` call, and if not, `on.exit()`s a `detach(..., unload = TRUE, force = TRUE)` so the build no longer leaves the caller's session permanently mutated; (2) *multi-output overwrite* — `entry$png_raw`/`entry$html` changed from scalar-overwritten-per-iteration to accumulated lists, so an example drawing two ggplots or rendering two gt tables keeps both, not just the last; (3) *eager `ggplot2`/`gt` `stop()`* — replaced with a lazy `requireNamespace()` check made inside the branch that already knows the example produced a ggplot/`gt_tbl` object, downgraded to a `capture_failures` entry (warn-and-skip, consistent with F6's policy) instead of hard-aborting capture for packages that never use plots/tables. Downstream `build_inline_example_outputs_map()` (`R/build_reference_files.R`) updated to emit `png`/`html` as JSON arrays; Rust side (`ExampleOutput.png`/`.html` in `options.rs`) changed `Option<String>` → `Option<Vec<String>>`, `emit_example_outputs` in `mdx.rs` now loops over every entry. New tests: `tests/testthat/test-capture-example-multi-output.R`. Full R suite (54/54) and Rust suite (12/12) passing. **Left open:** the deeper design question of whether in-session `library()` + `globalenv()`-parented eval is acceptable at all (vs. a per-file subprocess) was accepted "for now" per Q4 in the original addendum and not revisited by this fix — only its two concrete correctness bugs (mutation leak, output loss) were addressed.
- **Severity: Medium · Category: B/D · Confidence: High**
- **Evidence:** `R/capture_example_output.R:65-79` attaches the target package with `library(pkg_name, ...)` into the *caller's* session and never detaches it; `:114` `eval_env <- new.env(parent = globalenv())` so example side effects (`<<-`, `options()`, attaching further packages) leak into the live session for the rest of the build. `:135-162` — `entry$png_raw`/`entry$html` are *overwritten* each iteration, so an example that draws two ggplots or two gt tables keeps only the **last**; base-graphics (`plot()`, `hist()`) produce no capturable value and are silently lost. `:57-62` hard-`stop()`s if `ggplot2` or `gt` (both only in `Suggests`, `DESCRIPTION:23-27`) are absent.
- **The issue:** in-session eval is accepted for now (Q4) — but the *correctness* is in scope: (a) capturing into `globalenv()`-parented envs after `library()` means later reference files render against a mutated session (order-dependent, non-reproducible); (b) multi-output examples lose content; (c) a package with **no** ggplot/gt examples still cannot build docs unless both packages happen to be installed, because the guard fires before any example is inspected.
- **Blast radius:** wrong/missing example outputs on multi-plot functions; spurious hard failures on minimal install footprints; subtle cross-file contamination.
- **Remediation:** accumulate a list of outputs per example instead of overwriting; make the ggplot2/gt requirement lazy (only when an example actually yields such an object) or downgrade to a warning-and-skip; document/limit the session mutation (at minimum `on.exit` detach). ~0.5-1 day.

### F8 — `audit_config` false-warns on `@rdname` grouped topics and `-package` doc links
- **Status: Fixed (2026-07-06).** `validate_link_target()` (`R/links.R`) now takes a `reference_slugs` parameter instead of `exported`, and compares the link's `./reference/<x>/` target against that set instead of NAMESPACE exports. `audit_config()` (`R/audit.R`) computes `reference_slugs` by calling the same `resolve_config_rd_files()` + `rd_file_to_slug()` that `build_site()` uses to decide which `.Rd` files actually become reference pages — so the audit's notion of "valid reference target" is now the single generated-page-slug source of truth, covering `@rdname`-grouped topics and `<pkg>-package` doc pages for free (no separate `-package` special case needed, since those Rd files are just topics like any other). `exported` is untouched everywhere else in `audit_config` (missing-export reporting still uses it). Regression tests in `tests/testthat/test-audit-reference-links.R`: unit tests on `validate_link_target` for the `-package` and `@rdname` cases, a still-flags-broken-links case, and an end-to-end `audit_config()` fixture package with an exported function, an `@rdname`-grouped pair of exports, and a package doc page, asserting no warning fires for the first two links and one still fires for a genuinely missing target.
- **Severity: Medium · Category: D · Confidence: High**
- **Evidence:** `R/links.R:194-205` validates a `./reference/<x>/` link by checking `<x>` against **NAMESPACE exports only**. But reference pages are keyed on Rd file/topic names (slugs), which under `@rdname` need not equal any export, and the package doc page `<pkg>-package` is never an export. `R/audit.R:350-352` (`match_single_reference`) *does* special-case `-package$` and delegates aliases to `expand_selector` — so the two audit code paths disagree on what a valid reference is.
- **The issue:** legitimate internal links (`./reference/<pkg>-package/`, `./reference/<rdname-topic>/`) emit "Reference link target not found" warnings, training users to ignore audit output — which defeats the audit that `build_site` runs up front.
- **Blast radius:** noisy, misleading warnings on any package using `@rdname` grouping or a package doc page (i.e. most). Confidence high on the mechanism; the user-facing severity is "erosion of trust in the audit."
- **Remediation:** validate reference links against the *generated page slugs* (or the Rd db topic/alias set) rather than exports, reusing the `-package`/alias logic already in `match_single_reference`. ~0.5 day.

### F11 — `\bold{}` is unmapped in the emitter; wrapped text is silently deleted, not just unstyled
- **Status: Fixed (2026-07-07).** `emit_command`'s `strong` arm (`src/rust/parser/src/emit/mdx.rs:129`) now also matches `bold` (`"strong" | "bold" => self.emit_strong(option, args)`). - **Severity: High · Category: B · Confidence: High**
- **Evidence:** `emit_command`'s match arm for `strong` (`src/rust/parser/src/emit/mdx.rs:129`, `"strong" => self.emit_strong(option, args)`) has no corresponding arm for `bold` — the standard Rd synonym for `\strong`. ## 5. What's good (preserve while fixing)

- **The Rd->`Node`->MDX core is genuinely well-structured.** Lowering is separated from emission, the emitter methods are small and single-purpose, code/math-mode depth counters are a clean way to handle context-sensitive escaping, and the frontmatter/desc extraction is careful. This is the part to protect while fixing the boundaries around it.
- **The insta snapshot approach is the right testing shape** for an emitter — the only problem is corpus coverage (F2) and that it isn't gated in CI (F9), both cheap to fix without changing the design.
- **Ownership boundaries for generated files are deliberate and documented** (`custom.css` never overwritten vs `starlightr.css` always; `index.mdx`/`package.json`/`.gitignore`/deploy workflow guarded by `overwrite=`). This is a thoughtful, consistent policy worth keeping as the model for how the tool coexists with user-owned site files.
