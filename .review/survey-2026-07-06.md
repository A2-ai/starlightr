## 1. Repository map

**Purpose.** `starlightr` is a pkgdown-style documentation-site generator: it
turns an R package's Rd files, vignettes, README, and NEWS into an Astro
Starlight site (Rd → MDX reference pages, Rmd → markdown articles, captured
example outputs embedded inline). Codebase type: **hybrid** — an R package
(orchestration/config layer, ~3.5k lines under `R/`), a Rust workspace exposed
via extendr (`src/rust/`, the Rd lexer/parser/MDX emitter), and a set of
JS/Astro/YAML site templates shipped in `inst/templates/`.

**Entry points** (all R exports, `NAMESPACE`):
- `build_site()` — `R/build_site.R:33`, the main orchestrator.
- `use_starlightr()` — `R/use_starlightr.R:21`, scaffolding.
- `audit_config()` — `R/audit.R:25`, config-vs-NAMESPACE audit (also run
  automatically at the top of `build_site`).
- `build_reference_files()` / `build_package_reference_docs()` —
  `R/build_reference_files.R:34,129`.
- `build_articles()` / `build_package_articles()` — `R/build_articles.R:28,161`.
- `render_reference()` — extendr wrapper (`R/extendr-wrappers.R:28`) →
  Rust `render_reference` (`src/rust/parser/src/lib.rs:126`).
- Config helpers: `add_card`, `add_action`, `add_reference`, `add_article`,
  `add_version`, `add_package`, `get_/set_reference_sections`,
  `get_/set_article_sections` — `R/config_helpers.R`.
- Note: Rust also exports `render_references` (dir-walking batch variant,
  `src/rust/parser/src/lib.rs:162`) with a generated wrapper at
  `R/extendr-wrappers.R:30`, but it is **not** in `NAMESPACE` and has no R
  callers (?).

There are no services, background workers, or scheduled tasks. The generated
site ships a GitHub Actions template (`inst/templates/deploy-docs.yml`) that
runs in *consumers'* repos, not here.

**Module inventory** (R layer):
- `R/build_site.R` (260) — pipeline orchestrator; `resolve_config_rd_files` /
  `resolve_config_rmd_files` (config→file resolution incl. one glob impl).
- `R/config.R` (93) — `read_config` (TOML + `modifyList` merge with
  `default_config()`); used **only** by `build_site` and
  `build_package_reference_docs`.
- `R/config_helpers.R` (836) — programmatic TOML editing via `tomledit`
  (read raw / modify list / rewrite whole file); all `add_*` helpers.
- `R/audit.R` (372) — NAMESPACE parsing, config-reference matching (second
  glob impl), link auditing.
- `R/sidebar.R` (507) — builds the Starlight sidebar **as a JS string** via
  sprintf; third glob impl (`expand_glob_patterns`), pkgdown selector
  expansion, Rd-db lookups for `@rdname`.
- `R/build_reference_files.R` (221) — reference pipeline: example capture →
  external-link map → per-file Rust render.
- `R/capture_example_output.R` (180) — parses and **evals `@examples` in the
  current R session**, captures ggplot (PNG), gt (HTML), and printed text.
- `R/build_articles.R` (402) — renders Rmd in a `callr` subprocess via
  `pkgload::load_all`, copies figures to `public/figures/<slug>/`, rewrites
  image paths, prepends frontmatter.
- `R/external_links.R` (99) — builds `pkg::topic → URL` JSON map from installed
  packages' `aliases.rds` + DESCRIPTION URL.
- `R/generate.R` (215), `R/versions.R` (155), `R/assets.R` (67),
  `R/pages.R` (179), `R/process.R` (49) — template rendering (whisker), version
  support files, asset/logo copying, index.mdx and news.mdx generation.
- `R/links.R` (254) — link classification/validation for the audit.
- `R/utils.R` (252) — `%||%`, `slugify`, `escape_quoted_string`, template I/O.
- `R/rd_postprocess.R` (49) — `evaluate_sexpr`; **no callers anywhere** (dead).
- `R/extendr-wrappers.R` — generated.

**Module inventory** (Rust, `src/rust/`):
- `lib.rs` + `document.rs` — extendr module glue + wrapper regeneration binary.
- `parser/src/parsing/` — `lexer.rs` (228, hand-rolled Rd lexer),
  `parser.rs` (221, recursive-descent to `Node` tree), `span.rs`.
- `parser/src/document/` — `node.rs` (Node enum + `lower()` dispatch),
  `sections.rs`, `list.rs`, `link.rs`, `code.rs` — lowering of raw commands
  into typed nodes (Section, List, Link, Code, ArgumentTable).
- `parser/src/emit/` — `mdx.rs` (788, the emitter: frontmatter, sections,
  argument tables, math/code modes, external links, inline example outputs),
  `options.rs` (its own serde TOML `Config` reader — reads **only**
  `[reference]`).

**Intended layering** (inferred from call graph): exported R functions →
R orchestration (config/capture/articles) → Rust `render_reference` for
Rd→MDX → whisker templates for site chrome. Data crosses the R↔Rust boundary
via file paths + two temp JSON files (external links, example outputs) rather
than in-memory structures.

**Most load-bearing files:**
1. `src/rust/parser/src/emit/mdx.rs` — every reference page's content passes
   through it; correctness of the whole product depends on it.
2. `R/build_site.R` — the only composition point; every build flows through.
3. `R/config_helpers.R` + `R/config.R` — config is read by three independent
   readers (see hypotheses); these define the de facto schema.

**Cross-cutting concerns:**
- *Errors*: R mixes `cli::cli_abort`, base `stop()`, `cli_warn`,
  warn-and-continue, and `message()`-and-swallow (example capture,
  `R/capture_example_output.R:122-127`). Rust converts everything to
  `extendr_api::Error::Other` strings via `ResultExt`
  (`parser/src/lib.rs:16-24`); parse errors get line/col context.
- *Config*: three readers — `read_config` (merged with defaults,
  `R/config.R:10`), `read_config_toml` (raw, `R/config_helpers.R:11`, used by
  audit + all helpers), and Rust `Config::read_config`
  (`parser/src/emit/options.rs:109`, `[reference]` only).
- *Logging*: `cli` alerts throughout R; Rust warns via `eprintln!`
  (`mdx.rs:141-147`).
- *Validation*: `audit_config` validates config↔NAMESPACE/links up front;
  input Rd/Rmd content itself is trusted.
- *Concurrency*: none (single-threaded R; `callr::r_safe` subprocess per Rmd;
  Rust is synchronous). Category C is essentially N/A for this repo.

**Build/test/CI shape:** R package with `configure`/`tools/config.R` writing
`src/Makevars` (cargo static lib, vendored-offline support, webR/WASM path).
CI is one workflow (`.github/workflows/R-CMD-check.yaml`): R CMD check on
Windows/macOS/Linux × R 4.5/4.6, deps via `rv`. **`cargo test` is not run in
CI** — the Rust snapshot suite (insta, 10 Rd corpus files × lex/parse/emit)
runs only via local `lefthook.yaml` pre-commit. R-side testthat coverage is
3 small unit tests (`tests/testthat/`). Rust dep `extendr-api` is pinned to
git `branch = "main"` (Cargo.lock committed).

## 2. Risk hypotheses (ranked)

### H1 — Silent content loss for unhandled Rd commands in the emitter
- **Hypothesis**: The MDX emitter drops the entire subtree of any Rd command it
  doesn't recognize (`\tabular`, `\preformatted`, `\pkg`, `\sQuote`,
  `\dQuote`, `\cr`, `\tab`, `\env`, `\option`, `\file`, `\var`, `\dots`,
  `\Sexpr`, …), emitting only an `eprintln!` note, so real packages get
  reference pages with missing sentences/tables and no build failure.
- **Signal**: `emit_command`'s catch-all arm (`mdx.rs:139-149`) prints
  "skipping Rd command" and emits nothing — args are discarded. The lowering
  whitelist (`node.rs:128-142`) covers ~30 commands; base R's Rd spec has ~70.
  The test corpus contains **no** occurrence of `\tabular`/`\pkg`/
  `\preformatted`/`\sQuote` (verified by grep over
  `parser/test_data/*.Rd`), so the gap is also untested.
- **If true, cost**: user-visible incorrect documentation (dropped prose,
  dropped tables) for any package using common Rd idioms — the product's core
  output is wrong while the build reports success.
- **Investigation sketch**: enumerate handled commands (union of
  `node.rs:128-142` and `mdx.rs:126-149`) against the Rd command list in
  "Writing R Extensions"; craft an Rd file with the top ~15 missing commands,
  run `emit_document`, and diff against `tools::Rd2HTML` output; grade each
  gap (drop-with-content vs metadata-only).
- **Confidence**: high.

### H2 — Config split-brain: R-side defaults never reach the Rust emitter
- **Hypothesis**: `default_config()`'s `reference` defaults (skip_sections,
  section_order, pagefind) are inert — the Rust side re-reads the raw TOML
  file itself, so a user without a `[reference]` table gets empty
  skip/order (Name/Alias/Keyword sections rendered into pages), contradicting
  what the R defaults promise. Key spellings have already drifted:
  `default_config()` uses `"docType"` (`R/config.R:66`) but the section key it
  must match is `"Doc Type"` (`sections.rs:27`), and the repo's own
  `_starlightr.toml` uses `"doc type"` — only the last one matches under the
  lowercase comparison in `node.rs:69-75`.
- **Signal**: `render_reference` receives a config **path** and calls
  `EmitOptions::from_file` (`parser/src/lib.rs:143`); the merged R config from
  `read_config` (`R/config.R:27`) is never serialized back. Three readers, no
  shared schema. The drifted spellings above.
- **If true, cost**: surprising output for minimal configs; silent no-op
  config keys; every new option must be wired in 2–3 places with no mechanism
  keeping them in sync.
- **Investigation sketch**: trace `skip_sections` end-to-end for (a) no
  config-file case — note `read_config`'s no-file branch can't even occur via
  `build_site`, which aborts earlier (`build_site.R:46`), so who is
  `default_config()` for?; (b) config without `[reference]`. Build a scratch
  package both ways and inspect emitted MDX for Name/Alias sections. Also
  check `merge_config`'s `modifyList` semantics on nested lists vs arrays.
- **Confidence**: high.

### H3 — Name/glob/escaping resolution implemented 3–4× with drift
- **Hypothesis**: "resolve a config reference to files" exists in three
  incompatible implementations, and "escape a string for
  JS/YAML/TOML" in four; they have already diverged, so audit, sidebar, and
  build can disagree about the same config entry.
- **Signal**: globs — `resolve_config_rd_files` (`build_site.R:193-201`,
  full-pattern `.*`, anchored, case-insensitive) vs `expand_glob_patterns`
  (`sidebar.R:134-149`, **trailing-star only**, strips every `*` anywhere,
  prefix-anchored only) vs `match_single_reference` (`audit.R:347-372`,
  anchored `.*`, case-insensitive, plus `-package` special case). Escaping —
  `escape_quoted_string` (`utils.R:131`), `make_sidebar_item` (`sidebar.R:11`,
  quotes only, no backslash), `make_sidebar_group` (`sidebar.R:42`, backslash
  then quote), Rust `escape_yaml` (`mdx.rs:572`); meanwhile
  `process_article_inline` (`build_articles.R:293-296`) and `process_news`
  (`process.R:35`) interpolate titles into YAML frontmatter **unescaped**.
- **If true, cost**: a pattern like `build_*` matches in the audit but renders
  differently in the sidebar; a title containing `"` breaks a generated page's
  frontmatter; fixes must be re-discovered per copy.
- **Investigation sketch**: table the three glob impls' behavior on the same
  inputs (`a*`, `*a`, `a*b`, mixed case); test a vignette title with a double
  quote end-to-end; decide the single-boundary remediation (one
  `resolve_refs()` + one `escape_*` module).
- **Confidence**: high (drift verified by reading; impact medium).

### H4 — No coherent partial-failure story in the build pipeline
- **Hypothesis**: `build_site` has no transaction/cleanup semantics: one
  malformed Rd aborts `build_reference_files` mid-loop (no `tryCatch` around
  `render_reference`, `build_reference_files.R:82-90`) leaving a half-written
  site; example-capture errors are `message()`d and silently truncate output
  (`capture_example_output.R:122-127`); missing files warn-and-continue. The
  de facto strategy is "whatever each layer does".
- **Signal**: cited lines; also Rust `render_references` `?`-propagates on the
  first bad file (`lib.rs:201-210`); `writeLines` outputs land incrementally
  under `output_path` with no staging dir.
- **If true, cost**: CI docs deploys can publish partial sites; users can't
  distinguish "example intentionally has no output" from "example crashed".
- **Investigation sketch**: trace an Rd parse error from Rust through
  `build_site`; inventory every warn/abort/swallow site in the pipeline and
  classify against a target policy (fail-fast with staging dir vs
  collect-and-report).
- **Confidence**: medium-high.

### H5 — Example capture runs in-session; articles run isolated (inconsistent, leaky)
- **Hypothesis**: `capture_rd_examples` `library()`s the target package into
  the *caller's* session and `eval()`s example code in an env parented to
  `globalenv()` (`capture_example_output.R:65-79,114`), so examples mutate the
  user's session (attached namespaces, options, RNG, plots) and the user's
  session mutates examples; articles by contrast get a clean `callr`
  subprocess (`build_articles.R:79-102`). Also requires ggplot2+gt
  unconditionally even if no example produces either
  (`capture_example_output.R:57-62`).
- **Signal**: cited lines; the asymmetry between the two capture paths in the
  same pipeline.
- **If true, cost**: irreproducible example output, contaminated interactive
  sessions, Suggests-packages becoming de facto hard deps of `build_site`.
- **Investigation sketch**: confirm no cleanup/`detach` after capture; check
  what happens when examples call `library()`, `set.seed`, `options()`;
  evaluate moving capture into the existing callr pattern.
- **Confidence**: medium-high.

### H6 — `pkg` argument not threaded through: articles always build against cwd
- **Hypothesis**: `build_articles` hardcodes
  `pkg_path <- normalizePath(".")` for `pkgload::load_all`
  (`build_articles.R:76`), ignoring the `pkg` the caller passed to
  `build_site(pkg=)` / `build_package_articles(pkg=)`; building docs for a
  package from outside its directory loads the wrong package (or errors), and
  README-convention figures are collected from `rmd_dir` while knitr writes
  them relative to the subprocess cwd.
- **Signal**: `build_articles()` has no `pkg` parameter at all;
  `build_package_articles` takes `pkg` but drops it when delegating
  (`build_articles.R:191-196`). Contrast `build_reference_files`, which
  threads `pkg` properly.
- **If true, cost**: documented API (`build_site(pkg = "/path")`,
  `build_site.R:3`) silently builds the wrong thing.
- **Investigation sketch**: run `build_package_articles(pkg = <other dir>)`
  from an unrelated cwd; also audit other cwd assumptions
  (`render_reference`'s relative `output_dir` resolves against Rust's cwd,
  `lib.rs:58-64`).
- **Confidence**: high that the code does this; medium that the use case is
  supported intent [Q5].

### H7 — Test coverage anti-correlated with risk; Rust tests not in CI
- **Hypothesis**: The riskiest code (emitter, config merge, sidebar
  generation, article path-rewriting regexes) has no tests exercised in CI:
  testthat covers 3 leaf utilities; the Rust insta suite is decent for the
  happy path but runs only in `lefthook` pre-commit, and its corpus contains
  only already-supported commands (see H1), so it can't catch regressions in
  the gaps.
- **Signal**: `tests/testthat/` (3 files, ~60 lines); `R-CMD-check.yaml` has
  no cargo-test step; corpus command census (survey step) shows only handled
  commands.
- **If true, cost**: refactors of `mdx.rs`/`sidebar.R` are unguarded in CI;
  contributor without lefthook silently skips the whole Rust suite.
- **Investigation sketch**: confirm R CMD check doesn't run cargo tests;
  enumerate which of H1–H6's failure modes would be caught by any existing
  test (prediction: none); sketch a CI step + adversarial Rd corpus.
- **Confidence**: high.

### H8 — Unpinned `extendr-api` git dependency (branch = "main")
- **Hypothesis**: the whole native layer builds against a moving branch
  (`src/rust/Cargo.toml` workspace deps); reproducibility currently rides
  solely on the committed `Cargo.lock`, and any `cargo update` or lockfile
  regeneration can break the build or change wrapper generation
  (`Config/rextendr/version: 0.4.2.9000` is also a dev version).
- **Signal**: `Cargo.toml:26` `git = "https://github.com/extendr/extendr",
  branch = "main"`; recent commit "update rextendr source".
- **If true, cost**: builds break at a distance; CRAN submission impossible in
  this form.
- **Investigation sketch**: check whether Cargo.lock pins a rev; check
  vendor.tar.xz story for offline builds; likely intentional/temporary [Q8] —
  cheap to confirm and time-box.
- **Confidence**: high it's true; low that it's news to the maintainer.

## 3. Questions for the maintainer

Each question notes the hypothesis it feeds and the default I'll proceed with
if unanswered.

1. **[→H1]** Is "unknown Rd command → drop content, print stderr note" an
   accepted v0.1 tradeoff, or a defect? Which commands do your real target
   packages (hyperion, scicalc, …) actually use? *Default: treat silent drops
   of content-bearing commands (`\tabular`, `\preformatted`, `\pkg`,
   `\sQuote`, `\dots`) as defects; metadata-only commands as acceptable.*
2. **[→H2]** Are `default_config()`'s `reference.skip_sections`/`section_order`
   *intended* to apply when the user's TOML lacks a `[reference]` table?
   (Today the Rust emitter reads the raw file and they don't.) *Default: yes,
   intended → report as a bug.*
3. **[→H4]** Should one malformed Rd abort the whole build (current behavior),
   or warn and continue? Is a partially-written output dir acceptable?
   *Default: abort is fine, but partial output without a clear signal is not.*
4. **[→H5]** Is in-session example execution a deliberate pkgdown-style choice,
   or is subprocess isolation the eventual intent? *Default: deliberate for
   now — review capture correctness, not the isolation choice itself.*
5. **[→H6]** Is `build_site(pkg = <not cwd>)` a supported use case, or is
   "run from the package root" the real contract? *Default: supported (it's
   the documented signature) → cwd hardcoding in `build_articles` is a bug.*
6. **[→H7]** Is there any CI I'm not seeing that runs `cargo test` (org-level
   workflow, another branch)? *Default: no → flag as a CI gap.*
7. **[→H3]** `add_*` helpers rewrite `_starlightr.toml` via
   tomledit list round-trip — is losing user comments/formatting in that file
   acceptable? *Default: acceptable, won't flag.*
8. **[→H8]** Is `extendr-api @ git main` deliberately temporary (waiting on a
   release)? *Default: yes → mention only the reproducibility guard, not the
   choice.*
9. **[targeting]** Which matters more right now: correctness of emitted MDX
   (Rust emitter) or robustness of the R orchestration/config layer?
   *Default: emitter correctness.*
10. **[→ parking lot]** Does anything consume the unexported Rust
    `render_references` dir-walking path? *Default: unused → candidate for
    deletion; note it lacks the internal-keyword filtering the R path has.*

## 5. Parking lot

One-liners noticed in passing; Pass 2 triages under low-hanging fruit.

- `R/rd_postprocess.R:12` — `evaluate_sexpr` has zero callers (dead file).
- `R/assets.R:23` — `file.copy("vignettes/public", public_dir, recursive=TRUE)`
  nests a directory: produces `public/public/`, almost certainly meant to merge
  contents.
- `R/process.R:35` + `R/build_articles.R:293-296` — titles interpolated into
  YAML frontmatter unescaped (a `"` in a vignette title breaks the page).
- `R/pages.R:127-141` — card title/description interpolated into MDX/JSX with
  no escaping.
- `R/sidebar.R:140` — `gsub("\\*", "", pattern)` strips *all* asterisks, so a
  non-trailing glob like `a*b` silently becomes prefix `ab`.
- `R/config.R:46-52` — `default_config()$navbar$left` is read by nothing
  (only `navbar$right` is consumed, `utils.R:146-156`).
- `README.md` says "Requires R >= 4.0"; DESCRIPTION says `R (>= 4.2)`.
- `src/rust/parser/src/parsing/lexer.rs:55-57` — `\r` is not a text boundary:
  CRLF Rd files keep `\r` inside `Text` tokens (Windows-authored packages).
- `R/extendr-wrappers.R:30` — `render_references` wrapper generated but not
  exported/documented; drifts from the R path (no internal filtering).
- `R/build_articles.R:269` — the build-dir-prefix-stripping regex is keyed to
  `starlightr-rmd-` tempdir naming *and* absolute-path shapes seen on macOS
  (`/private/var/...`); fragile but self-contained.
